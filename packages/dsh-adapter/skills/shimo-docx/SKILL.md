# Word 默认风格（公文版式）

收到保存成功回执（含专用表格工具返回 saved）后，用 DSH 的 `present` 交付这份最终文件一次。只交付本次完成的文件，创建占位和写入失败时保留现场。

桌面端切换会话时，编辑器会等待原会话重新显示。实时工具返回 `no-editor` 时，告知用户切回这条会话，回到原路径用读取工具确认文件和写入进度，再继续实时写入。已经创建的文件只读回恢复，不再次新建同名或改名文件，也不要用脚本另出一份。

## 项目计划（实时生成）

用户要求写项目计划、项目计划书或项目启动计划时，即使没有要求“看过程”，也自动使用实时流程。不要调用脚本生成完整文档，也不要让用户指定工具或动画。文档标题和正文从空白开始逐段出现，正文写到里程碑位置后，Agent 再框选表格区域，准备完成后在原位整体出现，整个页面不刷新。

1. 确定里程碑条数（1–12 条，缺少具体要求时通常 4 条），然后立即调用 `document_create(path, template="project-plan", projectMetadata={milestoneCount: 条数})`。缺失资料写待填写；用户要求模拟时才使用模拟内容。创建后 `document.paragraphs` 含 11 个视觉上空白的正文段落和表格段落；正文段落中的不可见定位字符只是临时标记，须用 `setText` 完整替换，不能保留或复制；根据返回的编号区分 `table: true` 的段落，不要修改表格内的段落。
2. 依次对 11 个非表格段落用 `document_edit` 的 `setText` 写入：标题「项目计划」、项目名称、负责人、项目周期、标题「项目目标」、项目目标正文、标题「工作范围」、工作范围正文、标题「项目计划与里程碑」、标题「风险与依赖」、风险正文。标题和小标题已有模板样式，不另设格式。前三行标签与内容之间分别用 5、9、5 个普通空格；未给的值用待填写。每次传最新 `readToken`，需要时先 `document_read`；每次一段或一小批，让用户看到生成过程。正文段落只写一段文字，不要在 `setText` 内使用换行。不要将缺失的事实编造为真实信息。
3. 正文写完后，调用 `document_finish_project_table(path, milestones=[{stage, deliverable, owner, deadline}, ...])`，数组条数必须与新建时的 `milestoneCount` 一致。工具在 Agent 框选区域内写表格并保存，然后一次显示整表；不要调用脚本、不要重新加载页面，也无需再调用 `document_save`。

生成停止或工具出错时，保留已写内容并如实说明，不得使用脚本覆盖打开的文件。

## 产品需求文档

用户提出产品需求、需求说明或 PRD 时，调用 `document_create(path, template="product-requirements")`，随后按文档返回的 16 个非表格段落依次用 `document_edit` 的 `setText` 实时写：标题、需求名称、负责人、更新日期、需求背景与目标、目标用户与使用场景、用户流程、功能规则、验收标准、待确认事项。每个章节标题与正文分别占一个段落；标记字符是空白定位用，全部替换。未提供的事实写待填写，用户要求模拟时才使用模拟内容。写完 `document_save`。

## 工作周报

用户要工作周报、工作日报或工作复盘时，调用 `document_create(path, template="weekly-report")`，按返回的 14 个非表格段落依次 `setText` 写入标题、工作主题、汇报人、汇报周期和五组标题／正文：工作进展与成果、关键指标、问题与原因、经验与改进、下一步计划。根据用户实际任务调整章节标题，保留版式；未提供的事实写待填写，明确要求模拟时才使用模拟内容。定位字符必须全部替换。每批一节，写完 `document_save`。

## 会议纪要

用户要会议纪要或会议记录时，先确定会议决定条数（1–12，未明确时按 3 条），调用 `document_create(path, template="meeting-minutes", meetingDecisionCount=条数)`。正文按返回的非表格段落依次 `setText` 写标题、会议主题、会议时间、参会人、记录人、会议决定标题、表格说明、待确认事项标题和正文。四个标签「会议主题」「会议时间」「参会人」「记录人」后依次使用 4、5、9、9 个普通空格，这是已确认的排版；直接按此写入，不要为对齐再搜索文件、计算字体或延迟生成。未给的信息写待填写。然后调用 `document_finish_meeting_table(path, decisions=[{decision,owner,deadline},...])`，数组条数等于新建时决定数。工具会在同一编辑器保存并整体显示表格，不用脚本、不刷新页面、无需再次保存。不要更改表格内段落。

## 项目建议书

用户要项目建议书时调用 `document_create(path, template="project-proposal")`。依据返回的段落编号，依次用 `setText` 替换全部不可见定位字符；保留原有空段、分页与样式。按项目需要撰写公司、标题、基本信息、执行概要、目的、目标、解决方案、项目大纲及预算说明；资料不足写待填写。完成正文后调用 `document_finish_proposal_table(path, rows=[...])`，预算固定五行（含最后的合计行），每行可填 description、quantity、unitPrice、amount；不足的条目填待填写。该工具保存并在原位置整体显示表格。不要更改表格段落。

## 正式信函

用户要求正式信函、商务信或邀请函时调用 `document_create(path, template="formal-letter")`。按照返回的非空定位段落依次 `setText` 写发信人、地址、电话、邮箱、日期、收件人及地址、称呼、三段正文、结束语和署名；不改原有空行。未给的资料写待填写。完成后 `document_save`。

## 空白文档

用户明确要求空白 Word 或没有合适模板时使用 `document_create(path, template="blank")`；若只要空白文件则直接保存，不预填示例；要生成内容时从空白段落按要求逐段写入。


**默认在右侧编辑器里实时写**（有 `document_create` 工具时）：文件在右侧 OfficeSDK 编辑器里一段段写出来，用户能看着，和 PPT 一样。红头公文、页码都用实时方式，不要因为是红头、要页码就改用离线脚本。

**只有下面这些情况才用离线脚本**，而且走离线前要在回复里用一句话告诉用户为什么没在右侧生成（例：「这份要放表格，右侧编辑器暂时插不了表格，所以改用脚本直接生成文件。」）：

- 要**普通表格**（会议纪要、项目计划和项目建议书的表格按上面的实时生成流程）；
- 要图片；
- 上行文带签发人（请示、报告：发文字号居左、右边「签发人：×××」）或信函格式；
- 一次要出多份；
- 没有 `document_create` 等实时工具；
- 用户明确说不用看过程、直接给文件。

## 实时方式

1. **先选模板，新建**：`document_create(path, template)`。
   - `redhead`：通知、函、请示、报告、批复、通报、决定、公告、通告、意见、纪要等公文，或用户给了发文机关标志（如「××局文件」），或直接说要「红头」。
   - `gongwen`（默认）：工作报告、方案、总结、制度、讲话稿等正式文档（同样的公文版式，没有红头）。
   - `basic`：普通文档（普通 A4，宋体）。
   三个模板都带页码（gongwen、redhead 是「— 1 —」，奇数页居右、偶数页居左；basic 居中）。页面设置、页眉页脚都在模板里，编辑器没有页面设置、页眉页脚接口，不要试图改纸张、页边距或页眉。实时版的红头没有离线版的「草稿 · 待核定」页眉。用户在输入框「灵感库」里选了 Word 模板时，消息里是「请使用「公文版式」样式生成 Word 文档。」这样的句子（「公文版式」= `gongwen`，「红头公文」= `redhead`，「普通 A4」= `basic`），会话上下文里还有一条「Inspiration library pick」写明模板名，就按它传 `template`；选的是「红头公文」时按下面第 2 步的红头流程写（先用 `setText` 改两段占位）。选的是「公文版式」但用户明确要红头，或给了发文机关标志时，改用 `redhead`（同一套公文版式加红头）。
2. **红头（redhead）**：新建后第 0 段是「【发文机关】文件」（红色 42pt 小标宋），第 1 段是「【发文字号】」（下面带红线）。第一次 `document_edit` 先用 `setText` 改这两段（带 `document_create` 返回的 `readToken`）：第 0 段写「××××文件」（机关名超过约 8 个字时，再用 `formatParagraph` 把第 0 段的 `size` 调到 36 或 30，免得折行），第 1 段写发文字号，如「×发〔2026〕12号」，没给的写【待填写发文字号】。然后在后面用 `insertParagraph` 写：标题（`style: "title"`）、主送机关（`firstLineIndent: 0`，以「：」结尾）、正文各节；最后写落款：署名、日期各一段，`align: "right"`、`firstLineIndent: 0`。需要版记（抄送、印发机关和日期）时，写在落款后面，`firstLineIndent: 0`。不要在红头上方再插标题。
3. **分段写**：每次 `document_edit` 写一部分，让用户看着内容出现：第一次写标题（红头先改好两段占位）和第一节，之后每次一节（一个标题加它的段落或清单）。gongwen、basic 新建后只有一个空段，第一段用 `insertParagraph`（`style: "title"`）写标题，不要用 `setText` 改这个空段（那样不会套上标题样式）。新段落都给 `style`：`title`、`heading1`（一、）、`heading2`（（一））、`heading3`（1.）、`body`；编号写进文字。清单用 `list: "bullet"` 或 `"number"`。附件另起一页用 `insertPageBreak`。每个操作一段，文字里不能换行。**实时方式暂时不能插普通表格**（项目计划的里程碑表格按上面的实时生成流程处理）：表格是这份文档的主要内容时，按上面的说法用一句话说明，再改用离线脚本出整份稿；表格只是一小部分时，可以问用户是否改成清单、继续在右侧写。新建的文件写入时不用用户逐次确认；用户点了「停止」后，之后每次都会弹确认。
4. **改已有文档**：先 `document_read`，定位到要改的已有文字后，先调用 `document_read(path, editTarget: {paragraph, readToken, find?})` 标出目标，再拟写改文。局部替换用 `find` 指明原文，整段修改省略它。已有 selection_rewrite ID 时按该选区处理。并发改写时，其他段落先完成也可沿用本次读取的 `readToken` 提交，遇到 `source-changed` 再重新读取并定位。使用读取结果的段落编号和 `readToken`；`setText` / `replaceText` / `formatParagraph` / `deleteParagraph` 按编号改，`after` / `before` 指定插入位置。修改已有文件每次都要用户在标签页确认。
5. **保存**：写完调用 `document_save`。没保存时改动只在编辑器里。
6. **没有回滚**：一次 `document_edit` 中途出错或用户点了停止，前面已完成的步骤留在编辑器里（没有保存），错误信息会写「Steps 1–N of M were applied…」。照实告诉用户完成到第几步、没有撤销；**不要说已回滚或已撤销**。接着先 `document_read` 看现状，再决定补写还是用 `deleteParagraph` / `setText` 改回。用户不想要这些内容时，由你用 document_edit 删掉，或请用户在编辑器里删。
7. **不要混用**：文件在右侧打开期间，不要用 shell、python 或其它工具改同一个文件；编辑器里的内容才是最新的。
8. 只写用户给的事实，不扩写（同下面离线方式第 2 条）。缺的要素写【待填写…】并在交付时列出。

## 离线脚本方式

只在上面列出的情况下用，并先在回复里用一句话说明为什么没在右侧生成。先按 `office-docx` 的要求调用 `load_workspace_dependencies` 拿到 Python 路径；然后**用本 skill 的生成脚本出稿**，不要自己从零写 python-docx 样式。脚本只读本目录资源，输出写到任务工作区。

### 先定模式

- `redhead`：文种是通知、函、请示、报告、批复、通报、决定、公告、通告、意见、纪要等公文，或用户给了发文机关标志（如"××局文件"）。加发文机关标志、发文字号、红线、主送、落款、附件、版记，页眉标"草稿 · 待核定"。
- `plain`：其他文档（工作报告、方案、总结、制度、讲话稿等）。同样的页面、字体、字号、行距和页码，没有红头、红线和草稿标记。
- `document_type` 只给公文填；工作报告、方案、总结等内部文档不要填 `document_type`（尤其不要填"报告"），并写 `"mode": "plain"`。
- 拿不准时写 `"mode": "auto"`：给了发文机关标志，或文种是公文类时出红头；文种为"报告""意见"但没有发文字号时按 plain 处理。

### 流程

1. **整理内容**。按 [references/input.md](references/input.md) 写 doc JSON（放任务工作区）。标题层级用中文编号写进文字：一、 →（一）→ 1. →（1），对应 `level` 1–4。表格用 `table` 块，清单用 `list` 块。
2. **只写用户给的事实，不扩写**。按用户给的要点组织成规范语句即可，篇幅与要点相当；不要自行增加数字、措施、机构、背景或段落（例如用户没提的"资金管理""保障措施"）。文号、日期、签发人、主送、印章等用户没给的，留空或写【待填写…】，交付时列出缺项。用户给了全文时保留原文。
3. **预检**：`"<python>" "<本 skill 目录>/scripts/gongwen_docx.py" --input doc.json --check-only`。看输出里的 `missing`（缺的关键要素）和 `warnings`（要人工核对的地方）。
4. **生成**：`"<python>" "<本 skill 目录>/scripts/gongwen_docx.py" --input doc.json --out <名称>.docx`。
5. **检查与交付**：按 `office-docx` 回读内容；需要看版面时加载 `office-render` 检查首页（红头、红线、标题、主送、首页有正文）、末页（落款、版记）和页码。用 `present` 交付最终 .docx，并说明缺项和字体替换风险。

### 风格要点（脚本已实现）

| 项目 | 规格 |
|---|---|
| 页面 | A4；上 37、下 35、左 28、右 26 mm；页眉 15、页脚 17 mm |
| 标题 | 二号（22pt）小标宋，居中，行距 32pt，长标题可用 `title_lines` 分行 |
| 正文 | 三号（16pt）仿宋_GB2312，固定行距 29pt，首行缩进 2 字 |
| 标题层级 | 一级黑体、二级楷体、三级四级仿宋，均 16pt，编号写在文字里 |
| 页码 | `— 1 —`，14pt 宋体，奇数页居右、偶数页居左，各空 1 字 |
| 表格 | 全框 0.5pt 黑线，表头黑体 14pt 居中，内容仿宋 14pt，行距 22pt，撑满版心，表题在上方居中 |
| 红头（redhead） | 发文机关标志 42pt 小标宋红色，按长度压缩字宽；发文字号居中（有签发人时左字号、右"签发人：楷体姓名"）；下方 1.5pt 红线 |
| 落款 | 署名与日期右对齐；`seal_mode: reserved` 时只预留"待盖章位置"，不盖章 |
| 附件 | 正文后"附件：1. ××"；有正文的附件另起页，"附件1"黑体 + 小标宋标题 |
| 版记 | 末页底部：抄送、印发机关与印发日期，上下黑线 |

详细参数与来源见 [references/format.md](references/format.md)。

## 字体

只写字体名，不带字体文件。默认用 方正小标宋（FZXiaoBiaoSong-B05S）、仿宋_GB2312、方正黑体、楷体_GB2312、方正书宋。目标电脑没有这些字体时会被替换并影响分页；需要按本机已装字体出稿时加 `--font-policy installed`，脚本按 `assets/style.json` 的回退顺序为每个角色选第一个已装字体。所有中文 run 都同时设置 `w:eastAsia`。

## 不做

不盖章、不签发、不发送；不支持多个签发人、联合行文；不导入已有 Word 模板（用户给模板时改用 `office-docx` 在副本上修改）。实时方式不做表格、图片、页眉文字、批注和页面设置（页码和页边距由模板提供），也不能自动撤销；需要时直接告诉用户。

实时模板（gongwen、redhead、basic）由 `scripts/build_live_templates.py`（python-docx，参数取自 `assets/style.json`）生成到 `templates/`。
